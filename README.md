# Медиа-фабрика

Небольшая «контент-фабрика»: инструменты, которые готовят посты и публикуют их в соцсети
через официальные API. Инструменты: постер (публикует один пакет) и завод (склад готовых
пакетов, правила и публикация по расписанию через постер); оба описаны ниже.

Ключи и токены хранятся только в файле `.env` в корне репозитория (`chmod 600`, в git не
попадает), по строке `ИМЯ=значение`. Имена переменных перечислены в `KEYS.md`, например
`FB_PAGE_KOTLETA_ID`, `FB_PAGE_KOTLETA_TOKEN`, `X_API_KEY`, `LINKEDIN_CLIENT_ID`. Значения
нигде в репозитории не хранятся и не печатаются.

## Постер

`python3 -m poster` публикует один **пакет поста** сразу в несколько сетей: страницу Facebook,
Instagram (бизнес-аккаунт), X и личный профиль LinkedIn. Для каждой сети в пакете свой текст
и своя картинка (или без картинки), поэтому пост не дублируется, а подогнан под сеть.
Только стандартная библиотека Python 3.12, ничего ставить не нужно. Подробный дизайн:
`docs/design/poster.md`.

### Настройка (один раз)

1. Ключи лежат в `.env` в корне репозитория (`chmod 600`, в git не попадает). Другой файл:
   `--env-file ПУТЬ` или переменная `MF_ENV_FILE` (например, из другой рабочей копии, где
   своего `.env` нет).
2. Имена переменных (полный список в `KEYS.md`; значения только в `.env`):
   - `LINKEDIN_ACCESS_TOKEN`, `LINKEDIN_TOKEN_EXPIRES_AT`, `LINKEDIN_PERSON_URN` —
     записывает команда `login linkedin`;
   - необязательные настройки: `META_GRAPH_VERSION` (по умолчанию `v27.0`),
     `LINKEDIN_API_VERSION` (`202610`), `X_MONTHLY_CAP_USD` (`5.00`), `X_PRICE_POST` (`0.015`),
     `X_PRICE_POST_WITH_URL` (`0.200`), `X_PRICE_POST_WITH_MEDIA` (`0.200`),
     `X_PRICE_MEDIA_UPLOAD` (`0.015`).
3. LinkedIn: в приложении на developer-портале LinkedIn добавить продукты «Share on LinkedIn»
   и «Sign In with LinkedIn using OpenID Connect», на вкладке Auth в «Authorized redirect URLs»
   внести ровно `http://localhost:8765/callback`. Затем:

   ```
   python3 -m poster login linkedin
   ```

   Команда печатает ссылку, вы нажимаете Allow, токен и срок действия (60 дней) записываются
   в `.env`. Продление — та же команда; за 7 дней до конца `status` и `publish` предупреждают.

### Пакет поста

JSON-файл в `content/packages/` (папка `content/` не попадает в git):

```json
{
  "schema": 1,
  "id": "2026-11-09-halving",
  "theme": "О чём пост (никуда не публикуется)",
  "variants": {
    "facebook":  {"text": "Длинный текст для страницы", "image": "halving.jpg"},
    "instagram": {"text": "Подпись #bitcoin", "image": "halving-square.jpg"},
    "x":         {"text": "Одна острая цитата"},
    "linkedin":  {"text": "Профессиональный угол", "image": "photos/desk.png"}
  },
  "meta": {"source": "chat"}
}
```

- Картинка без `/` — имя из библиотеки `content/images/` (другая папка: `--library` или
  `MF_IMAGE_LIBRARY`); с `/` — путь к файлу (относительный — от папки пакета).
  Картинки отправляются как есть.
- Instagram без картинки невозможен — такой пакет отклоняется. Instagram принимает только JPEG.
- Лимиты проверяются до любого запроса: X — 280 взвешенных символов (кириллица 1, эмодзи 2,
  ссылка 23) и не больше 1 кештега; Instagram — 2200 символов, 30 хештегов, 20 упоминаний;
  LinkedIn — 3000 символов после экранирования. Длинный текст **не обрезается**: пакет
  отклоняется с подсчётом, и не уходит ни в одну сеть.

### Публикация

```
python3 -m poster publish content/packages/2026-11-09-halving.json --profile kotleta --dry-run
python3 -m poster publish content/packages/2026-11-09-halving.json --profile kotleta
```

- `--dry-run` показывает для каждой сети точный текст, картинку, подсчёты и все запросы
  (секреты скрыты), ничего не отправляет и ничего не записывает.
- Профиль: `kotleta` (Facebook, Instagram, LinkedIn, X). Отдельные цели: `--targets fb:kotleta,x`;
  любая другая страница — `fb:ИМЯ`/`ig:ИМЯ`, если в `.env` есть её переменные (см. `KEYS.md`).
- Порядок: Facebook, Instagram, LinkedIn, X (платная сеть последней). Ошибка одной сети не
  останавливает остальные; в итоге по строке на сеть.
- Повторный запуск того же пакета пропускает уже опубликованное и повторяет упавшее. Если
  исход неизвестен (обрыв связи или ответ 5xx после отправки), сначала проверьте аккаунт, затем
  `--force-target ЦЕЛЬ`.
- Коды выхода: `0` — всё опубликовано; `1` — хотя бы одна сеть упала или исход неизвестен;
  `2` — ошибка в команде или пакете, ничего не отправлено.

### Остальные команды

- `python3 -m poster delete --target fb:kotleta --post-id ID` — удалить пост страницы
  Facebook, опубликованный этим постером (сначала пост читается тем же токеном, после удаления проверяется, что он исчез).
- `python3 -m poster records --last 20` — журнал публикаций (время, пакет, цель, id, ссылка).
- `python3 -m poster status` — расход X за месяц, срок токена LinkedIn, какие цели настроены.
- `python3 -m poster check-staging --page kotleta ФАЙЛ.jpg` — проверка пути картинки для
  Instagram (временное неопубликованное фото на странице, затем удаляется); ничего не публикует.

### Бюджет X

Каждый запрос к X заранее записывается в месячный журнал расходов по цене из настроек. Если
пост выведет месяц за `X_MONTHLY_CAP_USD` (5 $), он отклоняется до любого запроса к X —
спросите оператора. Пост с картинкой пока считается по 0,215 $, пока реальная цена не видна
в X Developer Console; после этого цены меняются в `.env`.

### Где лежит состояние

Журнал публикаций и расходов X — вне репозитория:
`~/.local/state/media-factory/poster/` (или `MF_STATE_DIR`, `--state-dir`). Права 700/600,
секретов там нет.

## Завод

`python3 -m factory` публикует заранее одобренные пакеты по расписанию: склад папок с
пакетами, правила «папка → сети, дни, часы», план и таймер на этом компьютере. Публикует
он через тот же постер, поэтому проверки, журнал постера и бюджет X общие. Дизайн:
`docs/design/factory.md`.

### Склад

Папка склада — `content/stock/<имя>/` (имя: строчные латинские буквы, цифры и `-`). В ней:

- `folder.json`: `{"schema": 1, "title": "Цитаты", "lane": "photo"}`; `lane` — `photo` или
  `text` (папку `text` нельзя направить в Instagram);
- пакеты постера (`*.json`, формат как выше). Порядок публикации — по имени файла, поэтому
  файлы называются `001-….json`, `002-….json`. `id` пакета уникален на весь склад и не
  совпадает с пакетами в `content/packages/`.

**Одобрение.** Оркестратор показывает в чате все варианты всех пакетов, и только после OK
оператора кладёт их на склад с полем `"meta": {"approved_by_operator": "2026-11-10"}`.
Пакет без этого поля завод не публикует никогда (`check` и `status` пишут «not approved»).

### Правила

Файл `content/rules.json`:

```json
{
  "schema": 1,
  "rules": [
    {"id": "quotes-main", "folder": "quotes",
     "targets": ["fb:kotleta", "ig:kotleta", "linkedin", "x"],
     "days": ["mon", "wed", "fri"], "hours": ["10:00"],
     "timezone": "Europe/Berlin", "status": "draft"}
  ]
}
```

- Часы — целые, от `06:00` до `23:00`; пояс — имя IANA. `status`: `draft` (черновик) или
  `active`. Необязательный блок `limits` меняет наши оценки частоты (по умолчанию в сутки и
  минимальный промежуток: Facebook 3 и 3 ч, Instagram 3 и 4 ч, LinkedIn 2 и 6 ч, X 4 и 2 ч).
- Команды: `rule new ID [--folder F --targets … --days … --hours … --timezone Z]` (черновик;
  по умолчанию папка `ID`, профиль `kotleta`, пн/ср/пт 10:00, пояс машины),
  `rule set ID …`, `rule start ID`, `rule stop ID`.
- `rule start` отказывает, и файл не меняется, если: папки нет или в ней нет готового пакета;
  цель неизвестна, нет её переменных в `.env` или истёк токен LinkedIn; папка `text` идёт в
  Instagram; за 14 дней сеть превысит лимит в сутки или промежуток; план X за этот или
  следующий месяц выходит за `X_MONTHLY_CAP_USD`.
- Запись файла: блокировка `rules.lock`, сверка SHA-256 с версией, с которой команда начала
  («rules changed elsewhere, reload»), атомарная замена, права 600. Файл можно править руками;
  потом `python3 -m factory check`.

### План и проверка

```
python3 -m factory check               # склад и правила; 0 — порядок, 2 — список проблем
python3 -m factory plan --days 30      # слоты, какой пакет куда, запас дней, когда кончится, X
```

`plan` показывает для каждой папки «runway N of 90 days» (на сколько дней хватит), дату
«content runs out», публикаций на 7 дней и прогноз X: потрачено + запланировано из лимита.

### Публикация по таймеру

`python3 -m factory tick` — один короткий проход:

- слот в пределах 15 минут после своего времени публикуется;
- после простоя (компьютер был выключен) из пропущенных за последние 12 часов публикуется
  только самый поздний слот каждого правила и не больше одного на сеть за проход, с проверкой
  промежутка после последнего реального поста; остальные отмечаются `missed`. Пакет
  пропущенного слота не расходуется — его берёт следующий слот, очередь просто сдвигается;
- перед вызовом постера слот записывается как `claimed`, поэтому повторный или параллельный
  запуск не публикует его второй раз;
- если пост в X вывел бы месяц за лимит, остальные сети публикуются вовремя, а X пропускается
  (`x: skipped (budget)`), и `status` просит спросить оператора;
- `--dry-run` показывает, что ушло бы сейчас (постер в режиме dry-run), и ничего не пишет.

Коды выхода: `0` — порядок; `1` — слот закончился ошибкой, неизвестным исходом, отказом
постера или прерыванием; `2` — ошибка команды или файла правил.

### Статус, повтор, прерванные слоты

- `python3 -m factory status` — последний проход таймера, 5 ближайших слотов, расход X,
  срок токена LinkedIn и что требует внимания.
- `python3 -m factory retry СЛОТ` — повторить упавшие сети слота: в постер уходят только они
  (удалённый пост не вернётся). Файл пакета перечитывается перед отправкой: без одобрения
  или с ошибкой повтор отклоняется (код 2), постер не вызывается. Автоматически ничего не
  повторяется. Неизвестный исход — сначала смотрите аккаунт, потом постер с `--force-target`.
  Слот, чей исход в журнале «неизвестен» без строки в журнале постера, тоже держит пакет
  занятым и виден в `status`.
- Если проход оборвался после `claimed`, следующий проход пишет `interrupted` (или `done`,
  если журнал постера уже показывает результат) и не публикует снова. Посмотрите аккаунт и
  запишите итог: `python3 -m factory resolve СЛОТ --published` или `--not-published` (тогда
  пакет вернётся в очередь).
- Пакет, который постер отверг из-за его содержания, «held», пока файл не изменят; так же —
  после двух слотов подряд, упавших во всех сетях.

### Таймер (systemd, пользовательский)

```
python3 -m factory timer --print
```

печатает два юнита (`media-factory-tick.service` и `.timer`, раз в 5 минут) с путём этой
копии и команды включения. Ставятся они только с согласия оператора.

### Где лежит состояние завода

Склад и правила — в `content/` (не в git; другая папка: `--content` или `MF_CONTENT_DIR`).
Журнал слотов `runs.jsonl`, `heartbeat.json` и блокировки — в
`~/.local/state/media-factory/factory/` (или `MF_FACTORY_STATE_DIR`, `--state-dir`), права
700/600, секретов там нет. Журнал публикаций и расходов X — общий с постером.

## Тесты

```
python3 -I -B -m unittest discover -s tests -t .
```

Без сети и без настоящих ключей; `-B` не оставляет `__pycache__` в папке.
